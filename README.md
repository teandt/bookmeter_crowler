# なにをするツール？

読書メーターの「読んだ本」「積読本」のリストをクロールして取得するツールです。

過去に似たようなツールを作っている人もいましたが古そうだったので作り直してみました。  
取得したデータをブクログ形式のCSVに出力出来るため、ブクログへの移行に使用出来ます。  
読んだ日付、本のタイトル、著者名が取得でき、必要に応じて書籍詳細をクロールして本のタイトルの正式版、ページ数、ASINコードを取得してSQLiteで保存します。

# 機能

| オプション | 機能 |
| --- | --- |
| `-st`, `--stacked` | 積読本リストを取得します。 |
| `-rd`, `--read` | 読んだ本リストを取得します。 |
| `-dt`, `--detail` | 両リストにある書籍のうち、詳細データがまだDBにない書籍の詳細を取得します。 |
| `-all`, `--all` | 積読本、読んだ本、書籍詳細を順番に取得します。 |
| `-ckst`, `--checkstacked` | DBの積読本リストと、対応する書籍詳細を表示します。 |
| `-ckrd`, `--checkread` | DBの読んだ本リストと、対応する書籍詳細を表示します。 |
| `-ckd`, `--checkdetail` | DBの書籍詳細を表示します。 |
| `-deldt`, `--deletedetail` | どちらのリストにも存在しない書籍の詳細データを削除します。 |
| `-csv`, `--csv` | ブクログ形式のCSVを出力します。詳細未取得の書籍がある場合は中止し、詳細があってもASINがない書籍は除外します。 |
| `-s`, `--search` | 詳細取得済みの書籍をタイトルで部分一致検索します。複数キーワードはAND条件です。 |
| `-t`, `--target` | 検索対象を `all`（既定値）、`read`、`stacked` から指定します。`--search` と同時に使用します。 |
| `-h`, `--help` | ヘルプを表示します。 |

取得データはSQLiteに保存します。Spiderの確認用にJSONファイルも出力します。レビューや本棚登録状態は取得しません。

# pipでインストールが必要なパッケージ

CIではPython 3.12を使用しています。主な依存パッケージはScrapy、python-dotenv、SQLAlchemyで、テスト用のpytest、pytest-covなども依存ファイルに含まれています。

依存関係の入力ファイルは `requirements.in`、CIと通常のインストールにはハッシュ付きの `requirements.lock` を使用します。リポジトリ直下で仮想環境を作成し、インストールしてください。

```bash
python3 -m venv venv
source venv/bin/activate
python3 -m pip install --require-hashes -r requirements.lock
```

依存パッケージを追加・更新する場合は、`requirements.in` を編集した後、Python 3.12の環境で `pip-compile` を使用して `requirements.lock` を生成・更新します。`pip-compile` は `pip-tools` に含まれ、通常の依存ファイルには含まれていないため、更新作業時に別途インストールします。

```bash
python3 -m pip install pip-tools
pip-compile --generate-hashes --output-file=requirements.lock requirements.in
```

# 設定

読書メーターのユーザーIDを、環境変数 `USER_ID` または `.env` ファイルで指定します。両方に指定した場合は環境変数が優先されます。ユーザーIDは、読書メーターのプロフィールURL `https://bookmeter.com/users/<ユーザーID>` に含まれる値です。

`.env` を使用する場合は、リポジトリ直下で次のコマンドを実行し、作成したファイルの `USER_ID` を自分のIDに変更してください。

```bash
cp cr_bookmeter/env/.env.example cr_bookmeter/env/.env
```

```dotenv
USER_ID="00000"
```

`.env` は起動時の作業ディレクトリから見た `./env/.env` を読み込みます。CLI・Web UIともに、以下の例のように `cr_bookmeter` ディレクトリへ移動してから起動してください。

環境変数だけで指定する例（リポジトリ直下から実行）:

```bash
cd cr_bookmeter
USER_ID="0000" python3 bookmeter_crawl.py -rd
```

この書き方の環境変数は、そのコマンドだけに適用されます。複数のコマンドで使う場合は、先に `export USER_ID="0000"` を実行してください。

`USER_ID` はモジュール読み込み時に参照されるため、検索・CSV出力・ヘルプ表示の場合も設定が必要です。未設定または空文字列の場合はエラーになります。

# 実行方法

リポジトリ直下で仮想環境を有効化し、`cr_bookmeter` に移動します。

```bash
source venv/bin/activate
cd cr_bookmeter

# 積読本・読んだ本・未取得の書籍詳細を順に取得する
python3 bookmeter_crawl.py --all

# 取得済みの書籍を検索する
python3 bookmeter_crawl.py -s キーワード1 キーワード2

# 読んだ本の中から検索する
python3 bookmeter_crawl.py -s キーワード -t read

# 詳細な引数を確認する
python3 bookmeter_crawl.py --help
```

オプション一覧は[機能](#機能)を参照してください。処理を指定せずに実行した場合や、`--target` だけを指定した場合はエラーになります。

# Web UI

CLI オプション相当の処理は、ブラウザからも実行できます。
詳細な仕様は[Web UIマニュアル](README_webui.md)を参照してください。

リポジトリ直下から起動する例:

```bash
source venv/bin/activate
cd cr_bookmeter
python3 bookmeter_web.py
```

起動後、ブラウザで以下を開きます。

```text
http://127.0.0.1:8000/
```

ポートを変更する場合は、同じく `cr_bookmeter` ディレクトリで以下のように指定します。

```bash
python3 bookmeter_web.py --port 8080
```

Web UI では、積読本リスト取得、読んだ本リスト取得、書籍詳細取得、すべて取得、DB確認、タイトル検索、不要詳細データ削除、ブクログ形式CSV出力を実行できます。

Web UIでは同時に1つのジョブを実行します。ジョブの実行待ち・実行中は、別のクロール、CSV出力、検索、DB確認、不要詳細データ削除などを開始できません。この制御はWeb UI内のもので、別途起動したCLIとの排他制御はありません。


# 処理の流れのイメージ

1. 指定された積読本・読んだ本リストを取得します。取得中はステージングテーブルに保存します。
2. 各リストのクロール終了理由が `finished` の場合に、そのリストを取得結果で置き換えます。ただし、取得結果が0件で既存データがある場合は置き換えません。終了理由が `finished` でない場合も、既存リストを保持します。
3. `-dt` が指定されていれば、リスト更新後のDBをもとに詳細未取得のURLを重複除去して取得し、書籍詳細を保存します。詳細未取得の書籍がなければクロールしません。

`--all` は `-st`、`-rd`、`-dt` の順で実行します。複数の処理オプションを指定した場合も、引数の記述順ではなく、クロール、不要詳細データ削除、DB確認、CSV出力、検索の順になります。

詳細取得は、書籍詳細のレコードが存在しない書籍だけが対象です。すでにレコードがある書籍は、ASINなどの項目が欠けていても `-dt` では再取得しません。

アクセス設定は `cr_bookmeter/cr_bookmeter/settings.py` にあります。同一ドメインの同時リクエスト数は1、ダウンロード遅延の設定値は1秒、再試行回数は最大5回です。503などのHTTPエラーや取得件数はログで確認してください。詳細レコードが保存されなかった書籍は、次回の `-dt` でも取得対象になります。

クロール終了時は、各Spiderの結果を `[crawl-summary]` として表示します。`finish_reason` が `finished` でない場合、またはリストの差し替えが見送られた場合（`swap=kept`）は `result=FAILED` となり、CLIは終了コード1を返します。Web UIもCLIの終了コードが0以外の場合はジョブを失敗として扱います。この終了コード判定は、すべての詳細データが揃ったことを保証するものではありません。

# データ

SQLiteの保存先は `cr_bookmeter/sqlite/bookmeter.db` です。CLIでの処理実行時やWeb UIのDB操作時に、DBファイルと不足しているテーブルを自動作成します。

積読本／読んだ本リストでは以下の情報を保存します。

| DBのカラム名 | 内容 |
| --- | --- |
| `num` | 自動採番される主キー。同じ書籍の複数の読書記録を保存できます。リストの置き換え時に採番し直されます。 |
| `book_id` | 読書メーターの書籍番号。Spiderの `id` に対応します。 |
| `title` | リスト上のタイトル。長い場合は省略されています。Spiderの `short_title` に対応します。 |
| `authors` | リスト上の著者名。現在の実装では最初の著者名だけを取得します。 |
| `date` | 読んだ本では読書日、日付未指定の場合は `日付不明`。積読本では通常 `NULL` です。 |
| `url` | 読書メーターの書籍詳細URL。 |

書籍詳細には `book_id` を主キーとして、`title`（詳細ページのタイトル）、`pages`（ページ数）、`amazon_url`、`asin` を保存します。ページに情報がない場合などは、項目が空になることがあります。

Spider確認用のJSONは、`cr_bookmeter` からの実行時に同ディレクトリの `output_stacked.json`、`output_read.json`、`output_details.json` に出力されます。

# ブクログ形式のインポート用CSVファイルの出力

書籍詳細の取得後、`cr_bookmeter` ディレクトリで実行します。

```bash
python3 bookmeter_crawl.py -csv
```

以下の11列を、ヘッダー行なし・全フィールドをダブルクォートで囲んだ形式で出力します。

```text
サービスID, アイテムID, 13桁ISBN, カテゴリ, 評価, 読書状況, レビュー, タグ, 読書メモ(非公開), 登録日時, 読了日
```

サービスIDは `1`、アイテムIDはASINです。読んだ本の読書状況は `読み終わった`、積読本は `積読` になります。読んだ本の読了日は保存済みの読書日を使用し、未設定または `日付不明` の場合は空欄です。積読本の読了日と、その他の列は空欄になります。

出力先は作業ディレクトリから見た `csv/booklog.csv`（上記手順では `cr_bookmeter/csv/booklog.csv`）で、既存ファイルは上書きします。文字コードはShift_JIS（Pythonの `sjis`）で、表現できない文字は置換されます。

CSV出力前に、積読本・読んだ本リストに対応する詳細データが揃っているかチェックします。詳細未取得の書籍がある場合は出力を中止するため、先に `-dt` で書籍詳細を取得してください。出力が中止された場合、既存のCSVファイルは更新されません。

詳細データが存在していてもASINがない書籍は、ブクログ登録に必要なアイテムIDを作成できないためCSV出力から除外します。ASINがある書籍はそのまま出力され、除外件数と対象書籍はログに出力されます。

Web UIの「前提条件を確認」ではASIN不足も表示しますが、CSV出力処理では該当書籍を除外して出力します。すべての書籍がASINなしの場合は、空のCSVファイルになります。

出力したファイルを、ブクログの[まとめて登録（CSV）](https://booklog.jp/input/file)から登録します。
